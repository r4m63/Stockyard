# Практическое задание: ПО для трейдинга и инвестиций

**Курс:** Разработка мобильных приложений
**Семестр:** Весна 2026
**Университет:** ИТМО, ФПИиКТ
**Преподаватель:** Ключев А.О.

---

## 1. Тема проекта

Разработать **экосистему для поддержания трейдинга и инвестиций** (аналог Тинькофф Инвестиции).

### Назначение системы
- Имитация бэкенда брокера, получающего информацию о котировках акций с «биржи».
- Имитация брокерского терминала для клиентов брокера (Android).
- Поддержка **10 000 клиентов**.

### Формат работы
- Групповой проект, рабочая группа **до 10 человек**.
- Делается приложение на Android **+ бэкенд**.
- Цель — **MVP** (минимально жизнеспособный вариант приложения) с документацией за семестр.
- Программы могут быть простыми, им разрешается иногда падать, в документации допускаются пробелы.

---

## 2. Состав системы (обязательные компоненты)

1. **Мобильное приложение для Android** — Kotlin + Jetpack Compose
2. **Кросс-платформенное мобильное приложение** — React Native (или подобные)
3. **Микросервис для связи с мобильными приложениями** — Ktor + Kotlin
4. **Микросервис для работы с БД** — Kotlin
5. **Микросервис-имитатор 10к мобильных приложений** — без GUI, рандомные запросы через API. Kotlin / Python / Go
6. **Микросервис для получения котировок** — Go
7. **Драйвер для Linux с имитацией котировок** — C

### Функции системы
- Получение данных от биржи.
- Выдача данных клиентам.
- Организация покупки/продажи акций в терминале.

## 6. Требования к отчёту (PDF)

### 6.1. Общее оформление
- Как в дипломе. Рекомендуется ГОСТ-оформление (с оглавлением, введением, заключением, списком литературы и красивыми картинками).
- Методичка: **Калинина М.И., Смирнов С.Б. Методические указания по выполнению ВКР для бакалавров. — СПб: Университет ИТМО, 2016. — 40 с.**
- Стандарты:
  - **ГОСТ 2.105-95** «Единая конструкторская документация. Общие требования к текстовым документам».
  - **ГОСТ 7.32-2017** «Отчёт о научно-исследовательской работе. Структура и правила оформления».

### 6.2. Титульный лист
- Название проекта.
- ФИО авторов.
- Руководитель.
- Организация — Университет ИТМО.
- Год.

### 6.3. Оглавление
- Создаётся автоматически через стили «Заголовок 1», «Заголовок 2» и т.д.
- Не более **3 уровней заголовков**.

### 6.4. Колонтитулы и номера страниц
- Внизу страницы (кроме титульного листа) — номер страницы.

### 6.5. Введение
Содержит:
- **Актуальность работы** — аргументы важности, нужности, своевременности и необходимости разработки.
- **Цели и задачи работы:**
  - Цель — ответ на вопрос «ЗАЧЕМ?», получение чего-либо полезного.
  - Задачи — последовательность действий для достижения цели.

### 6.6. Раздел 1: Техническое задание
За основу — **ГОСТ 19.201-78** «Техническое задание, требования к содержанию и оформлению».

#### Структура ТЗ:
- Введение.
- Назначение разработки.
- Требования к программе или программному изделию:
  - Функции системы.
  - Состав системы.
  - Характеристики системы.

#### Алгоритм написания ТЗ:
1. Составить список заинтересованных лиц.
2. Составить список важных аспектов разработки (инструментальный, прикладной, надёжность, безопасность, энергопотребление и т.п.).
3. Составить список требований для каждого заинтересованного лица.
4. Оценить сроки, бюджет и возможности разработчиков.
5. Сформулировать ТЗ, которое возможно выполнить и которое удовлетворит заказчика.

### 6.7. Раздел 2: Архитектура системы
- ⚠️ **Самый важный раздел. Делается самостоятельно (без ИИ).**
- Должна позволять понять, как устроен проект внутри: из каких частей состоит, как они связаны и взаимодействуют.
- Адресаты: технические руководители, архитекторы, старшие разработчики.
- Глубина — до уровня создания спецификаций для рядовых программистов.
- Сложный и ответственный раздел, требующий много времени.

### 6.8. Раздел 3: Описание реализации
- Описание тонкостей реализации классов, методов и структур данных.
- Документирование желательно **без отрыва от исходных текстов** (Dokka, комментарии в коде).

### 6.9. Раздел 4: Тестирование
Используем **только три вида тестов**:
- **Модульное** — юнит-тесты отдельных классов (механизм встроен в IntelliJ IDEA).
- **Интеграционное** — тестирование подсистем, микросервисов, библиотек.
- **Системное** — вся система целиком.

Для интеграционного и системного тестирования — разработать **тестовое инструментальное обеспечение** на Kotlin / Go / Python.

### 6.10. Заключение
- Результаты и достижения, полученные в процессе работы.
- Результат — выполненная задача из начала документа.
