# ADR-006: Argon2id для хэширования паролей

## Status
**Accepted** (2026-05-09)

## Context

Пользователи регистрируются и логинятся по паре email + пароль. Нужно безопасно хранить пароли: **никогда в открытом виде**, устойчиво к brute-force и rainbow tables, с защитой от ускоренных атак на GPU/ASIC.

## Decision

Используем **Argon2id** — победитель Password Hashing Competition 2015, рекомендованный OWASP с 2024 года. Параметры:
- `memory = 19 MiB`
- `iterations = 2`
- `parallelism = 1`
- встроенная соль (16 байт)

Реализация:
- Kotlin: `de.mkammerer.argon2-jvm` (привязка к нативной libsodium).
- Хэши хранятся в `users.password_hash` в формате PHC: `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>`.

Хэширование выполняется в **DB Service** (не в Gateway), чтобы пароль не покидал security-границы дольше необходимого.

## Consequences

**Положительные:**
- Современный стандарт, GPU/ASIC-resistant за счёт memory-hard функции.
- Встроенная соль — не нужно отдельное поле в БД.
- Параметры подбираются под конкретное железо; легко увеличить cost при апгрейде серверов.

**Отрицательные:**
- **CPU-затратно по дизайну**: одна верификация — 30–80 мс на типовом CPU.
  - При burst-логине (например, прогон Load Simulator с 10к одновременных регистраций) DB Service может стать bottleneck не по PostgreSQL, а по CPU хэширования.
  - Митигация: вынести вычисление в отдельный пул потоков (`Dispatchers.IO` с увеличенным размером), не блокировать пул для бизнес-логики ордеров. См. [08. Масштабирование](../08-scaling.md) — это явное допущение.
- Memory-cost требует ~20 МБ на одну верификацию — нужно учитывать при `parallelism > 1` на сервере.

**Нейтральные:**
- Параметры PHC сохраняются в самом хэше, поэтому при апгрейде cost старые пароли остаются валидными до следующего успешного логина (можно ре-хэшировать в этот момент).

## Alternatives considered

- **bcrypt**:
  - Тоже хорош и широко распространён.
  - Уступает Argon2id по защите от GPU-атак.
  - OWASP с 2024 предпочитает Argon2id.
- **scrypt**:
  - Memory-hard, но сложнее настраивать; меньше зрелых библиотек для Kotlin.
- **PBKDF2**:
  - Не memory-hard; уязвим к параллельным GPU-атакам.
  - Допустим только если требуется FIPS-сертификация (нам не нужна).
- **plain SHA-256 / SHA-512 / MD5**:
  - Категорически нет. Не имеют memory-cost; ломаются GPU за минуты.
- **Хэширование на клиенте**:
  - Не защищает от утечки БД (хэш и есть пароль с точки зрения сервера).
  - Усложняет смену алгоритма.
